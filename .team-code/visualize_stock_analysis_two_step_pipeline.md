## 1. End-User Requirements Verification

### The Profitable Stock Trader
- **Demand Fulfilled**: Instant local access to visual performance reports without spinning up a local web server or facing browser CORS blocks. Traders can double-click any generated `.html` report directly in Windows Explorer, macOS Finder, or Linux file managers.
- **Trading Value**:
  - Standalone `.json` files are generated by `scripts/stock_analysis_data.py` or alongside every HTML report with identical naming (`<SYMBOL>_analysis_report_<DATE>.json`).
  - Headless CLI `python scripts/stock_analysis_data.py -s AAPL` provides rapid terminal access to trading levels and data contracts without browser invocation.
  - Traders can reuse the `.json` file with `--from_json` in `visualize_stock_analysis.py` to re-render the HTML report instantly (e.g. after updating custom templates or CSS themes) without waiting for heavy quantitative re-calculations.
  - All interactive charts, AVWAP lines, Volume Profile POC/VAL/VAH, GEX strikes, BOCD regime pins, PEAD surprise tables, Best Buy toggles, and tooltips function with identical visual fidelity and zero latency.

### The Institutional Hedge Fund Manager
- **Methodological Rigor**: Clean separation of concerns between analytical data computation & serialization (`stock_analysis_data.py`) and presentation/visualization rendering (`visualize_stock_analysis.py`).
- **Data Contract & Pipeline Integration**:
  - The analytical engine produces a standardized, versioned JSON data contract (`contract_version: 1.0.0`) encompassing all model modules:
    1. `metadata`: Symbol, request date, data freshness, forecast duration, and generation timestamp.
    2. `historical_data`: Sanitized OHLCV bars with rolling 50/200 SMAs and YTD Anchored VWAP dispersion bands ($\pm 1\sigma$).
    3. `performance`: 1Y, 3Y, 5Y historical CAGR, drawdowns, Sharpe ratios, and win rates.
    4. `best_buys`: Ranked historical cyclical troughs and technical inflection points.
    5. `predictive`: 3-month strategic forecast, optimal entry zones, stop losses, and risk/reward ratios.
    6. `projections`: Multi-period forward returns (6M, 1Y, 2Y, 3Y) conditioned on regime, microstructure, and derivatives.
    7. `regime`: Bayesian Online Changepoint Detection (BOCD), run-length, changepoint hazard $P(r_t=0)$, vol surface ratio, and macro credit momentum.
    8. `microstructure`: Anchored VWAP (YTD, 52W High, 52W Low), volume-weighted dispersion bands, and continuous Volume Profile (KDE).
    9. `derivatives`: Net Dealer Gamma Exposure (GEX), Gamma Flip point ($S^*$), Call/Put Walls, Max Pain, and Variance Risk Premium (VRP).
    10. `events`: Corporate catalyst awareness, FOMC/CPI macro calendars, pre-earnings de-grossing haircuts, Standardized Unexpected Earnings (SUE), and PEAD momentum drift.
  - Headless batch pipelines can run `stock_analysis_data.py` (or `visualize_stock_analysis.py --json_only`) to export raw JSON data into quantitative lakes or downstream automated risk engines without rendering HTML overhead.

## 2. Architectural Design & Function Specifications

```
+-------------------------------------------------------------------------------+
|                       DECOUPLED TWO-STEP ARCHITECTURE                         |
+-------------------------------------------------------------------------------+
                                        |
               [scripts/stock_analysis_data.py - Data Contract Engine]
                                        |
        run_stock_analysis() / compute_multi_period_projections()
                                        |
                         prepare_analysis_json_payload()
                                        |
                            export_analysis_json()
                                        |
                        Writes: <SYMBOL>_report_<DATE>.json
                                        |
                                        v
             [scripts/visualize_stock_analysis.py - Presentation]
                                        |
                             load_analysis_json()
                                        |
             +--------------------------+--------------------------+
             |                                                     |
  Modular Card Builders                                 Embedded JSON Payload
  - build_projection_cards_html()                       <script id="report-data"
  - build_regime_card_html()                                    type="application/json">
  - build_microstructure_card_html()                      {json_embedded_payload}
  - build_derivatives_card_html()                       </script>
  - build_events_card_html()                                       |
             |                                                     |
             +--------------------------+--------------------------+
                                        |
                             generate_html_dashboard()
                                        |
                        Writes: <SYMBOL>_report_<DATE>.html
                                        |
                           [Client Browser Execution]
                JSON.parse(document.getElementById('report-data'))
```


### 1. `resolve_json_path(symbol, report_dir=None, output=None, report_date=None) -> Path`
* Computes the companion `.json` file path matching the HTML report name.
* Guarantees identical base naming (e.g. `NVDA_analysis_report_2026-09-04.json` paired with `NVDA_analysis_report_2026-09-04.html`).

### 2. `_sanitize_for_json(obj: Any) -> Any`
* Recursively converts complex numerical structures into native JSON-serializable primitives:
  - `np.nan`, `np.inf`, `-np.inf` $\rightarrow$ `None` (JSON `null`).
  - `np.integer` $\rightarrow$ `int`.
  - `np.floating` $\rightarrow$ `float`.
  - `datetime.date`, `datetime.datetime`, `pd.Timestamp` $\rightarrow$ ISO 8601 string.
  - `pd.DataFrame` $\rightarrow$ list of dictionaries.
  - `pd.Series` $\rightarrow$ list of values.

### 3. `prepare_analysis_json_payload(analysis_data: Dict[str, Any]) -> Dict[str, Any]`
* Converts raw analysis dictionary containing DataFrames into the canonical schema dictionary.
* Pre-calculates 50-day and 200-day moving averages and continuous AVWAP envelopes across the entire historical price series.
* Guarantees all modular components (`regime`, `microstructure`, `derivatives`, `events`, `projections`) are present and sanitized.

### 4. `export_analysis_json(analysis_data: Dict[str, Any], json_path: Union[str, Path], indent: int = 2) -> Path`
* Executes **Step 1**: Serializes the canonical data contract and writes formatted UTF-8 JSON to disk.
* Automatically creates missing parent directories.

### 5. `load_analysis_json(json_path: Union[str, Path]) -> Dict[str, Any]`
* Executes **Step 2 (Input)**: Reads and deserializes the JSON data contract from disk with rigorous existence checks.

### 6. Modular HTML Card Builders
* Refactored into discrete, testable components:
  - `build_projection_cards_html(projections: Dict[str, Any]) -> str`
  - `build_regime_card_html(regime: Optional[Dict[str, Any]]) -> str`
  - `build_microstructure_card_html(micro: Optional[Dict[str, Any]]) -> str`
  - `build_derivatives_card_html(derivatives: Optional[Dict[str, Any]], spot_price: float = 0.0) -> str`
  - `build_events_card_html(events: Optional[Dict[str, Any]]) -> str`

### 7. `generate_html_dashboard(data_input, output_path, json_path=None) -> Path`
* Executes **Step 2 (Rendering)**: Accepts either a path to a `.json` file or an analysis dictionary.
* Ensures companion `.json` file is exported to disk if missing.
* Embeds the canonical JSON payload inside `<script id="report-data" type="application/json">` with proper `</script>` escaping.
* Injects client-side JavaScript initialization:
  ```javascript
  const REPORT_DATA = JSON.parse(document.getElementById('report-data').textContent);
  const RAW_HISTORY = REPORT_DATA.historical_data || [];
  const BEST_BUYS = REPORT_DATA.best_buys || [];
  const PREDICTIVE = REPORT_DATA.predictive || {};
  const PERFORMANCE = REPORT_DATA.performance || {};
  const DERIVATIVES = REPORT_DATA.derivatives || {};
  const EVENTS = REPORT_DATA.events || {};
  const MOMENTUM_EVENTS = (EVENTS && EVENTS.momentum_events) ? EVENTS.momentum_events : [];
  ```

## 3. CLI Options & Execution Modes

The command-line interface supports three operational modes:

1. **Standard Two-Step Mode (Default)**:
   ```powershell
   python scripts/visualize_stock_analysis.py --symbol NVDA --report_dir reports
   ```
   - Executes Step 1: Computes quantitative models and exports `reports/NVDA_analysis_report_<DATE>.json`.
   - Executes Step 2: Loads `reports/NVDA_analysis_report_<DATE>.json` and renders `reports/NVDA_analysis_report_<DATE>.html`.

2. **JSON Export Only Mode (`--json_only`)**:
   ```powershell
   python scripts/visualize_stock_analysis.py --symbol NVDA --report_dir reports --json_only
   ```
   - Executes Step 1 only. Skips HTML generation for headless computational pipelines.

3. **Render from JSON Mode (`--from_json`)**:
   ```powershell
   python scripts/visualize_stock_analysis.py --from_json reports/NVDA_analysis_report_2026-09-04.json --report_dir reports
   ```
   - Executes Step 2 only. Renders HTML dashboard directly from existing JSON dataset without needing `--symbol` or recalculating models.

6. `test_generate_html_dashboard_from_path_string`: Validates passing a JSON file path directly to the dashboard generator.
7. `test_backward_compatibility_with_raw_dict`: Verifies passing raw engine dictionary automatically writes companion JSON and generates HTML.
8. `test_modular_card_builders`: Unit tests all 5 card builders with populated and empty inputs.
9. `test_cli_from_json`: Validates CLI execution with `--from_json`.
10. `test_cli_json_only`: Validates CLI execution with `--json_only`.
